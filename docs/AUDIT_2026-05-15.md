## Executive Findings

1. `P1 [MHS RED FLAG] [THREE-ONLY]` The presentation layer is deeply coupled to Three.js. `Game.ts`, `LevelBuilder.ts`, `TileKit.ts`, hazard classes, backdrop/decor modules, `AssetRegistry.ts`, and procgen debug all construct or mutate Three objects directly. This is fine for the web prototype, but the MHS port should not attempt a line-by-line translation. Use `GeneratedLevel`, `HazardSpawnSpec`, `CourseSurface`, `RailCapsule`, and asset keys as the stable bridge.

2. `P1 [MHS RED FLAG] [THREE-ONLY] [TEST GAP]` Simulation code still leaks Three.js vector types. `SimpleBallPhysics.ts`, `DragShotInput.ts`, `TileCatalog.ts`, `TilePlacementSolver.ts`, and `procgenModelScale.ts` use `THREE.Vector2`, `THREE.Vector3`, `THREE.Box3`, or `THREE.MathUtils` in logic that should survive the engine change. Porting should introduce engine-neutral math DTOs/utilities before MHS implementation.

3. `P1 [MHS RED FLAG] [BROWSER-ONLY]` Platform services are web-specific. DOM HUD, `innerHTML` overlays, pointer events, URL query flags, `localStorage`, WebAudio, Vite entrypoints, and clipboard debug actions have no direct MHS runtime equivalent. They need platform adapters or replacement UI/services.

4. `P1 [LEGACY]` The game still has a dual level-generation story: procgen endpoint is the shipped/default path, but `LevelGenerator`, legacy path helpers, legacy procedural tile render paths, and fallback metadata remain. This is useful for QA/bisecting, but it increases porting scope unless deliberately marked "web only" or retired.

5. `P1 [MHS RED FLAG] [THREE-ONLY]` Runtime asset loading and cloning (`GLTFLoader`, `FBXLoader`, `AssetRegistry.getModelClone`) must become MHS asset templates/prefabs. MHS should not load arbitrary GLB/FBX at runtime the way the web prototype does.

6. `P2 [TEST GAP]` Automated tests are concentrated in procgen and hazard selection. Physics, rails, ramps, portal collision/teleport behavior, UI state, economy/progression persistence, and asset registry contracts lack direct tests.

7. `P2 [BROWSER-ONLY] [TEST GAP]` UI uses template strings and `innerHTML` in `GameOverlays.ts` and debug bootstrap code. Some strings are escaped, but DOM construction is not consistently typed or componentized. This is a web-maintenance risk and a porting rewrite surface.

8. `P2 [MHS RED FLAG]` Asset footprint is close to the snackable guardrail cited in `docs/mhs-port/SNACKABLE_ALIGNMENT.md` before packaging overhead. Large GLBs and high-resolution UI PNGs should be optimized or split by build flavor.

9. `P2 [LEGACY]` `procgenDebugInfo?: Record<string, unknown>` and other loose debug fields are useful in the web prototype but should not be shipping payload contracts. MHS runtime should consume strict `GeneratedLevel`-style data and keep debug extras optional or editor-only.

10. `P3` Tooling hygiene: remove unused `@emnapi/core` and `@emnapi/runtime`, add/handle Python tooling explicitly for `strip:ui-bg`, and simplify redundant Knip config patterns.

## Architecture Hotspots

### `src/core/Game.ts`

- `P1 [THREE-ONLY]` Owns scene, camera, renderer, lights, course groups, requestAnimationFrame, animation mixers, and object disposal.
- `P1 [MHS RED FLAG]` Also owns gameplay lifecycle, audio, HUD, overlays, collectibles, hazards, and level loading. For porting, split "game state + loop decisions" from "Three scene mutation."
- `P2 [TEST GAP]` High-value behavior such as OOB recovery, hole scoring, portal finish flow, stuck skip, and reward timing is mostly manual-test only.
- Simplification: extract a pure `HoleSession` or `RunController` that consumes `GeneratedLevel` and emits view/audio/UI commands.

### `src/procgen/TilePlacementSolver.ts`

- `P1 [MHS RED FLAG]` Uses Three vectors as construction scratch for otherwise engine-neutral grid/pivot math.
- `P1 [TEST GAP]` Contains many high-impact branch cases: double-row curves, ramps, portal gaps, floor repair, rail orientation. Smoke tests cover regressions but not a full invariant matrix.
- Simplification: move vector operations to a tiny neutral `Vec3Like` helper and expand seed replay cases for recent tile alignment/z-fight bugs.

### `src/procgen/MapGenerationEndpoint.ts`

- `P1 [LEGACY]` "Endpoint" is an in-process frontend service, not an HTTP API. It retries, imperfectly matches difficulty, and falls back to safe maps.
- `P2 [TEST GAP]` Fallback/imperfect-difficulty behavior should have explicit tests and a port-facing doc table.
- Simplification: separate candidate generation, validation, difficulty scoring, portal application, and fallback selection into smaller units.

### `src/style.css`

- `P2 [BROWSER-ONLY]` Large monolithic DOM stylesheet, including HUD, overlays, FTUE, run summary, and leaderboard. None of this ports directly to MHS UI.
- `P2` Recent additions and older sections share global class space. Keep for web prototype, but for porting treat only state labels and UI data as reusable.
- Simplification: split CSS by feature (`hud`, `overlays`, `ftue`, `debug`) if web maintenance continues.

### `src/procgen/ProcgenDebugViewer.ts`

- `P1 [THREE-ONLY] [BROWSER-ONLY]` Dev viewer owns its own renderer, OrbitControls, toolbar assumptions, debug labels, sockets, hazard preview, and undermap/decor scene.
- `P2 [MHS RED FLAG]` Useful tooling should be redesigned as an editor utility scene or prefab validation tool, not shipped runtime code.
- Simplification: keep it web-only, but ensure it consumes the same strict `GeneratedMap`/`GeneratedLevel` contracts as gameplay.

### `src/level/tiles/TileKit.ts`

- `P1 [THREE-ONLY]` Builds procedural geometry, attaches FBX/GLB models, creates hole visuals, animated flags, rails, grass, overlays, and fallbacks.
- `P1 [MHS RED FLAG]` Tile mesh placement rules are fragile and asset-pivot dependent; the MHS port should turn tile asset keys into prefabs with tested base-footprint/pivot metadata.
- `P2 [TEST GAP]` No automated asset-footprint tests yet. Recent fixes around 200x200 grass bases should become contract tests.

### `src/level/procgenLevelAdapter.ts`

- `P1` This is one of the strongest port seams. It converts procgen maps into `GeneratedLevel`, surface patches, rail colliders, hazard specs, portals, and bounds.
- `P2 [LEGACY]` It still bridges into legacy tile types and legacy builder assumptions. That is acceptable now, but the MHS port should consume the adapted DTO directly.
- `P2 [TEST GAP]` Add tests for portal midpoint spawn, finish portal conversion, exposed rail sides, ramp surface patches, and strict validation errors.

### `src/ui/Hud.ts` and `src/ui/GameOverlays.ts`

- `P1 [BROWSER-ONLY]` Direct DOM, image tags, event listeners, timers, `innerHTML`, and local CSS class contracts. MHS UI should be a replacement, not a port.
- `P2 [TEST GAP]` HUD state is not covered by DOM tests. Recent leaderboard, skip row, callouts, seed display, FTUE, and run summary are manual-test only.
- Simplification: define a serializable UI state model (`HudState`, `OverlayState`) and make DOM/MHS adapters render from it.

1. `P1 [LEGACY]` Decide the future of `LevelGenerator`. Either retire after procgen confidence is high or isolate as "web QA fallback only." Do not port both level pipelines by default.
2. `P2 [LEGACY]` Review `railSides`, `railWorldSides`, `railOriginX/Z`, `assetKeyOverride`, and `procgenDebugInfo` for a strict MHS v1 payload. Keep only the fields MHS runtime actually consumes.
3. `P2` Split `Game.ts` into engine-neutral state progression and Three view/controller adapters.
4. `P2` Split `TileKit.ts` into procgen prefab placement metadata, legacy procedural fallback visuals, and hole/cup visuals.
5. `P2` Split `style.css` by feature if web UI will continue changing.
6. `P2` Make `AssetRegistry` produce an audit table: key, file, size, type, loaded-in-game, debug-only, MHS prefab target.
7. `P3` Clean Knip findings: unused `@emnapi/*`, unlisted Python binary, redundant Knip patterns.
8. `P3` Clarify docs that `MapGenerationEndpoint` is an in-process generator, not a network endpoint.

## Recommended Test Additions

- `SimpleBallPhysics`: flat settle, ramp ascent/descent, rail capsule collision, bridge void, portal handoff, OOB recovery.
- `courseSurface`: local/world sampling for flat and ramp patches, rotated patches, gaps returning null.
- Procgen seed replay: include recent seeds for tile alignment, z-fight prevention, portal gaps, start/hole caps, curved double-row rails.
- Asset contracts: every `AssetKey` resolves to an existing file; procgen tile FBXs obey 200x200 grass-base metadata; no duplicate unused hazard formats ship unintentionally.
- UI: DOM smoke tests for HUD mount, leaderboard open/close, skip row, callout image fallback, run summary escaping.
- Persistence: economy, cosmetics, quests, telemetry, FTUE state migration/default tests.
