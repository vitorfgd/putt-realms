# Putt Realms Audit - 2026-05-15

Target port: Meta Horizon Studio / Horizon Engine (MHS/MHE).

This audit covers the current workspace, including uncommitted changes. It started as documentation-only; the action-pass notes below track the port-readiness refactors and tests now implemented against this audit.

## Severity And Tags

- `P0`: blocks port or causes known gameplay breakage.
- `P1`: high-risk architecture, likely port blocker, or repeated bug source.
- `P2`: cleanup/simplification with meaningful maintenance value.
- `P3`: nice-to-have polish or documentation debt.

Tags:

- `[MHS RED FLAG]`: must be replaced, wrapped, or redesigned for MHS/MHE.
- `[THREE-ONLY]`: direct Three.js APIs, scene graph, geometry, materials, shaders, loaders, animation, raycasters.
- `[BROWSER-ONLY]`: DOM, localStorage, WebAudio, URL query flags, Vite/web assumptions.
- `[LEGACY]`: fallback generator paths, compatibility fields, duplicated procgen/legacy behavior.
- `[TEST GAP]`: risky behavior without direct automated coverage.

## Executive Findings

1. `P1 [MHS RED FLAG] [THREE-ONLY]` The presentation layer is still deeply coupled to Three.js. `Game.ts`, `LevelBuilder.ts`, `TileKit.ts`, hazard visual classes, backdrop/decor modules, `AssetRegistry.ts`, and procgen debug all construct or mutate Three objects directly. This is fine for the web prototype, but the MHS port should not attempt a line-by-line translation. Use `GeneratedLevelV1`, `MhsSpawnManifest`, `HazardSimulationContract`, `CourseSurface`, `RailCapsule`, and prefab keys as the stable bridge.

2. `P1 [MHS RED FLAG] [THREE-ONLY]` Portable gameplay/procgen logic is now mostly separated from Three vector classes. `SimpleBallPhysics.ts`, `TileCatalog.ts`, `MapGenerationTypes.ts`, `TilePlacementSolver.ts`, and `MapGenerationEndpoint.ts` use engine-neutral DTO/math primitives. Remaining Three-only math is concentrated in web adapters, render/debug code, runtime model bounds, and decor/undermap helpers.

3. `P1 [MHS RED FLAG] [BROWSER-ONLY]` Browser-only services are now partially behind adapters. Storage, debug flags, clock, telemetry, and audio have platform-service seams, and `localStorage` is contained in `BrowserStorageService`. DOM HUD/overlays, pointer events, WebAudio implementation details, Vite entrypoints, and clipboard debug actions still have no direct MHS runtime equivalent.

4. `P1 [LEGACY]` The game still has a dual level-generation story: procgen endpoint is the shipped/default path, but `LevelGenerator`, legacy path helpers, legacy procedural tile render paths, and fallback metadata remain. This is useful for QA/bisecting, but it increases porting scope unless deliberately marked "web only" or retired.

5. `P1 [MHS RED FLAG] [THREE-ONLY]` Runtime asset loading and cloning (`GLTFLoader`, `FBXLoader`, `AssetRegistry.getModelClone`) must become MHS asset templates/prefabs. MHS should not load arbitrary GLB/FBX at runtime the way the web prototype does.

6. `P2 [TEST GAP]` Automated coverage is much broader, but not complete. Physics, surfaces, seed replay, prefab contracts, session commands, storage services, and UI state now have tests. Remaining gaps include full DOM smoke tests, all hazard runtime effects, reward timing, FTUE panels, and larger Game adapter lifecycle flows.

7. `P2 [BROWSER-ONLY] [TEST GAP]` UI uses template strings and `innerHTML` in `GameOverlays.ts` and debug bootstrap code. Some strings are escaped, but DOM construction is not consistently typed or componentized. This is a web-maintenance risk and a porting rewrite surface.

8. `P2 [MHS RED FLAG]` Asset footprint is close to the snackable guardrail cited in `docs/mhs-port/SNACKABLE_ALIGNMENT.md` before packaging overhead. Large GLBs and high-resolution UI PNGs should be optimized or split by build flavor.

9. `P2 [LEGACY]` `procgenDebugInfo?: Record<string, unknown>` and other loose debug fields are useful in the web prototype but are excluded from the strict `GeneratedLevelV1` projection. MHS runtime should consume `GeneratedLevelV1` plus prefab metadata and keep debug extras optional or editor-only.

10. `P3` Tooling hygiene is currently clean. The unused `@emnapi/*` packages were removed, the `python` script binary was documented for Knip, redundant Knip patterns were simplified, and `npx knip` passes.

## Action Plan Implementation Notes

- Added `GeneratedLevelV1` as the MHS-facing projection and kept `procgenDebugInfo` / `procgenSourceMap` out of that payload.
- Added engine-neutral math primitives and moved `SimpleBallPhysics` off direct Three.js vector construction.
- Added platform/session/UI/prefab seams: `HoleSession`, `PlatformServices`, `HudState`, `OverlayState`, and `MHS_PREFAB_REGISTRY`.
- Expanded automated coverage from the audited 17 tests to include physics, course surface sampling, the recent procgen seed, asset/prefab contracts, strict level projection, and UI state defaults.
- Cleaned Knip findings by removing unused `@emnapi/*`, simplifying `knip.json`, and documenting the intentional `python` script binary.

- Added browser implementations for storage, audio, debug config, telemetry, and clock services, then wired `Game.ts` through the browser platform bundle.
- Added `HazardSimulationContract`, `MhsSpawnManifest`, expanded `MHS_PREFAB_REGISTRY` metadata, and `WebOnlyModules` so the MHS port can distinguish portable data from web-only rendering/debug code.
- Added the port-readiness roadmap, `ShotIntent`, pure hazard-effect evaluation, expanded `HoleSessionCommand` coverage, prefab planning metadata, asset optimization backlog, and static HUD/overlay DOM contract tests.
- Added `npm run compress:models` and compressed six oversized embedded JPEG textures from 2048px to 1024px quality 72, saving 17,013,772 bytes across those GLBs.
- Added final 3D MHS handoff contracts for static bootstrap planning, render-world state, object/template identity, replication/lifetime intent, template child names, AudioHub event IDs, and server-owned persistence planning.

## Architecture Hotspots

### `src/core/Game.ts`

- `P1 [THREE-ONLY]` Owns scene, camera, renderer, lights, course groups, requestAnimationFrame, animation mixers, and object disposal.
- `P1 [MHS RED FLAG]` Also owns much of the gameplay lifecycle, HUD, overlays, collectibles, hazards, and level loading. Audio/storage/debug services now enter through `createBrowserPlatformServices`, but the class is still the largest web adapter.
- `P2 [TEST GAP]` High-value behavior such as OOB recovery, hole scoring, portal finish flow, stuck skip, and reward timing is mostly manual-test only.
- Simplification: continue moving lifecycle decisions into `HoleSession` commands until `Game.ts` mostly wires Three rendering, input, audio, HUD, overlays, and session events.

### `src/procgen/TilePlacementSolver.ts`

- `P1 [MHS RED FLAG]` Now uses neutral math scratch objects for grid/pivot placement. Keep it data-only.
- `P1 [TEST GAP]` Contains many high-impact branch cases: double-row curves, ramps, portal gaps, floor repair, rail orientation. Smoke/contract tests cover recent regressions but not a full invariant matrix.
- Simplification: keep extending seed replay cases for tile alignment, z-fight prevention, portal gaps, and rail exposure.

### `src/procgen/MapGenerationEndpoint.ts`

- `P1 [LEGACY]` "Endpoint" is an in-process frontend service, not an HTTP API. It retries, imperfectly matches difficulty, and falls back to safe maps.
- `P2 [TEST GAP]` Fallback/imperfect-difficulty behavior now has direct contract coverage, but candidate scoring remains dense and should be split if the generator continues to grow.
- Simplification: separate candidate generation, validation, difficulty scoring, portal application, and fallback selection into smaller units.

### `src/style.css`

- `P2 [BROWSER-ONLY]` Large monolithic DOM stylesheet, including HUD, overlays, FTUE, run summary, and leaderboard. None of this ports directly to MHS UI.
- `P2` Recent additions and older sections share global class space. Keep for web prototype, but for porting treat only state labels and UI data as reusable.
- Simplification: split CSS by feature (`hud`, `overlays`, `ftue`, `debug`) if web maintenance continues.

### `src/procgen/ProcgenDebugViewer.ts`

- `P1 [THREE-ONLY] [BROWSER-ONLY]` Dev viewer owns its own renderer, OrbitControls, toolbar assumptions, debug labels, sockets, hazard preview, and undermap/decor scene.
- `P2 [MHS RED FLAG]` Useful tooling should be redesigned as an editor utility scene or prefab validation tool, not shipped runtime code.
- Simplification: keep it web-only, but ensure it consumes the same strict `GeneratedMap`/`GeneratedLevel` contracts as gameplay.

### `src/level/tiles/TileKit.ts`

- `P1 [THREE-ONLY]` Builds procedural geometry, attaches FBX/GLB models, creates hole visuals, animated flags, rails, grass, overlays, and fallbacks.
- `P1 [MHS RED FLAG]` Tile mesh placement rules are fragile and asset-pivot dependent; the MHS port should turn tile asset keys into prefabs with tested base-footprint/pivot metadata.
- `P2 [TEST GAP]` Asset file and prefab mapping tests exist, but source-model pivot/base-footprint validation is still metadata-driven rather than verifying geometry offline.

### `src/level/procgenLevelAdapter.ts`

- `P1` This is one of the strongest port seams. It converts procgen maps into `GeneratedLevel`, surface patches, rail colliders, hazard specs, portals, and bounds.
- `P2 [LEGACY]` It still bridges into legacy tile types and legacy builder assumptions. That is acceptable now, but the MHS port should consume the adapted DTO directly.
- `P2 [TEST GAP]` Portal midpoint spawn, exposed rail sides, ramp surface patches, and strict projection coverage exist. Expand next into negative validation/error cases.

### `src/ui/Hud.ts` and `src/ui/GameOverlays.ts`

- `P1 [BROWSER-ONLY]` Direct DOM, image tags, event listeners, timers, `innerHTML`, and local CSS class contracts. MHS UI should be a replacement, not a port.
- `P2 [TEST GAP]` HUD state is not covered by DOM tests. Recent leaderboard, skip row, callouts, seed display, FTUE, and run summary are manual-test only.
- Simplification: define a serializable UI state model (`HudState`, `OverlayState`) and make DOM/MHS adapters render from it.
